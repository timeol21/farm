# washcar-test 编译与部署：两条路线

> 简短版：**两条路线都可用，产物都落在项目内，互不干扰。**
> 你选哪条看现场条件，不用改任何代码。

## 0. 一句话选择

| 你的情况                        | 走哪条               |
| --------------------------- | ----------------- |
| 盒子能装编译器、想现场改代码、网络不方便传大包     | **路线 A：盒子本机编译**   |
| 盒子内存小/没装编译器、要批量出包、想在电脑上盯着日志 | **路线 B：WSL 交叉编译** |

两条路线的产物结构完全一样（`deployed/` 里 `main` + `libmosquitto.so.1`），
跑起来的行为也一样 —— 区别只在「在哪编」。

---

## 1. 路线 A：盒子上编译

### 1.1 盒子上要装什么（一次性）

```bash
sudo apt-get install -y build-essential cmake
```

**只需要这两个。** mosquitto 和 nlohmann/json 的库与头文件都内置在仓库的
`third_party/` 里，不用 `apt install libmosquitto-dev`。
（如果盒子上恰好装了系统的 `libmosquitto-dev`，CMake 会优先用系统的，也是对的。）

### 1.2 把源码传上去

在 Windows 的 WSL / Git Bash 里：

```bash
rsync -av --delete \
  --exclude 'build-wsl' --exclude 'build-box' --exclude 'deployed' \
  washcar-test/ ztl@<盒子IP>:/home/ztl/program/washcar-test/
```

源码总共约 **1 MB**（含 third_party）。别再传 `washcar-val` 那种带 `lib/` 的整包。

### 1.3 盒子上：自检 → 编译 → 跑





```bash
ssh ztl@<盒子IP>
cd /home/ztl/program/washcar-test

bash check-box-env.sh      # ① 只读自检，不改任何东西
bash build-on-box.sh       # ② 编译 + 组装 + ldd 校验（约 1 分钟）
bash build-on-box.sh run   # ③ 冒烟跑 5 秒
```

日常改完代码就一句：

    JOBS=3 bash build-on-box.sh

```bash
bash build-on-box.sh
```

### 1.4 产物位置

```
washcar-test/build-box/main        带符号（gdb 用）
washcar-test/build-box/src/main    CMake 原始位置，同一份
washcar-test/deployed/main         strip 后（体积约 1/2）
washcar-test/deployed/libmosquitto.so.1
washcar-test/deployed/config.json   首次运行自动生成
```

### 1.5 常用参数

```bash
JOBS=4 bash build-on-box.sh              # 内存够就开 4 路（默认 2）
bash build-on-box.sh clean               # 删 build-box/ 和 deployed/
BUILD_DIR=/tmp/b bash build-on-box.sh    # 构建目录换地方
```

### 1.6 编译完怎么跑

```bash
cd deployed && ./main         # 前台，Ctrl+C 停
```

已验证 `deployed/main` 通过 `RUNPATH=$ORIGIN` 加载同目录的 `libmosquitto.so.1`，
不需要设 `LD_LIBRARY_PATH`，也不往系统目录塞东西。

## 2. 路线 B：WSL 交叉编译

### 2.1 首次搭环境（电脑上，一次性）

```bash
wsl
cd /mnt/e/Desktop/washcar-main/washcar-test
sudo bash wsl-cross/setup-env.sh
```

会装 `gcc-9-aarch64-linux-gnu` + 搭 `/opt/rk3568-sysroot`（约 2–3 GB，5–20 分钟）。

### 2.2 编译

```bash
bash wsl-cross/build-wsl.sh            # 增量（改 1 个 .cpp 约 12 秒）
bash wsl-cross/build-wsl.sh rebuild    # 全量重来（约 1 分钟）
```

或者用快捷键：

```bash
bash wsl-cross/dev.sh build    # 编译
bash wsl-cross/dev.sh test     # 跑测试
bash wsl-cross/dev.sh run      # qemu 跑起来看日志
bash wsl-cross/dev.sh clean    # 清构建目录
```

产物：`deployed/`（`main` + `libmosquitto.so.1` + `config.json`；main 为 ARM aarch64，strip 后约 3.2 MB）

> 与路线 A 落在同一个目录。构建目录 `build-wsl/` 只存中间产物（.o），ccache 在项目内 `.ccache/`。

### 2.3 部署到盒子

```bash
BOX_HOST=ztl@<盒子IP> BOX_PASS=<密码> bash wsl-cross/deploy-wsl.sh
```

脚本会传 `main` + `libmosquitto.so.1`（有 `config.json` 也一起传），
然后在盒子上跑 `ldd` 校验，看到「所有依赖库均已解析」就成功。

`BOX_PASS` 用完即弃，不要写进脚本或提交仓库。

## 3. 首次运行必须改的三个配置

不管走哪条路线，`./main` 第一次跑都会在**可执行文件同目录**生成 `config.json`，
然后停下改这三项再重启：

| 配置项              | 默认值             | 改成                                                   |
| ---------------- | --------------- | ---------------------------------------------------- |
| `box.boxNo`      | `123456`        | **每台盒子唯一编号**（同时是 MQTT clientId 和 topic 前缀，两台撞号会互踢下线） |
| `plcSerial.port` | `/tmp/vplc-pty` | 海天真 PLC 一般 `/dev/ttyUSB10`                           |
| `box.boxType`    | `haiTian`       | 驿公里改成 `yiGongLi`（走 Modbus TCP，见 `plcTcp.*`）          |

`mqtt.*` 默认 `116.204.32.197:1883` / `admin`，一般不用改。

## 4. 怎么判断"跑正常了"

启动后看到这些就是正常，后面报 PLC / MQTT 失败都算预期：

```
 washcar-test 洗车机主控（PLC + MQTT 精简版）
>>> 初始化 PLC (boxType=haiTian, boxNo=...)
>>> 初始化设备服务层
  - 采集周期 500ms (来自 config.json 的 machine 段), 点位 29 项, 服务 4 项
>>> 初始化 MQTT
[MQTT] 已连接, topic=flexem/<boxNo>/command
[MQTT] 已订阅 flexem/<boxNo>/command
>>> 系统启动完成，按 Ctrl+C 停止
```

`[MQTT] 已订阅` 这一行是硬指标 —— 说明云端已经能给它下发命令了。

## 5. 报错对照表

| 现象                                                        | 原因                                             | 处理                                                                                         |
| --------------------------------------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `error while loading shared libraries: libmosquitto.so.1` | 部署目录里缺这个 .so，或 RUNPATH 丢了                      | 跑 `bash build-on-box.sh` 让它重新组装；手工兜底 `LD_LIBRARY_PATH=. ./main`                            |
| `libssl.so.1.1: cannot open shared object`                | 盒子缺 OpenSSL 1.1                                | `sudo apt-get install -y libssl1.1`                                                        |
| 编译报 `找不到 mosquitto`                                       | `third_party/mosquitto` 没传全，或目录里的库是 0 字节空壳     | 见下面 5.1；`ls -l third_party/mosquitto/lib/aarch64/` 必须看到 101400 字节的 `libmosquitto.so.1.6.9` |
| 编译全过但链接报 `undefined reference to mosquitto_xxx`           | 库没进链接命令行（老 CMake 不认 `.so.1.6.9` 这种文件名），或库文件传坏了 | 用当前版本的 `CMakeLists.txt`（会把文件摆成 `libmosquitto.so`）；先 `bash build-on-box.sh clean` 再编        |
| 编译报 `找不到 nlohmann/json.hpp`                               | 同上                                             | 确认 `third_party/nlohmann/json.hpp` 在                                                       |
| 编译被 OOM kill                                              | 盒子内存小                                          | `JOBS=1 bash build-on-box.sh`                                                              |
| `PLC] fx_plc_01 连接失败`                                     | 串口没接 / 端口错                                     | 改 `plcSerial.port`；`ls -l /dev/ttyUSB*` 看真实设备名                                             |
| `[MQTT] 正在连接...` 一直不出现「已连接」                               | 网络/防火墙/Broker                                  | `check-box-env.sh` 第 6 节会探测 broker 可达性                                                     |
| `./main: Permission denied`                               | 传文件丢了可执行位                                      | `chmod +x deployed/main`                                                                   |

### 5.1 third_party 里的 libmosquitto 为什么只放一个文件

`third_party/mosquitto/lib/aarch64/` 里**只有一个实体文件**：

```
libmosquitto.so.1.6.9      约 99 KB
```

没有 `libmosquitto.so`，也没有 `libmosquitto.so.1`。这是故意的，别手工补。

原因是一次真实踩坑：最早这个目录里做了 `libmosquitto.so` / `libmosquitto.so.1` 两个软链，
在 WSL 里编译一切正常；但源码从 Windows 传到盒子时，软链要么被丢掉，要么变成一个
**0 字节的同名空文件**。于是 CMake 里「`EXISTS libmosquitto.so` 就认为库齐全」的判断
失效，盒子端直接报：

```
找不到 mosquitto（头文件=MOSQ_INCLUDE_DIR-NOTFOUND 库=MOSQ_LIBRARY-NOTFOUND），
且 third_party 里没有适配本架构的副本
```

现在的处理方式（不再依赖任何软链）：

- CMake `file(GLOB)` 扫 `libmosquitto.so*`，**谁在就用谁**，短名字优先，并跳过 0 字节文件；
- 选中后先校验 ELF 魔数（`7f454c46`），文件传坏了当场报错，不会拖到链接阶段；
- **把实体文件复制到 `build-box/third_party-libs/libmosquitto.so` 再链接**。这一步是必须的：
  直接链 `libmosquitto.so.1.6.9` 这种非标准文件名，老版本 CMake（Ubuntu 20.04 自带的 3.16）
  认不出它是共享库，会把它从链接命令行里丢掉，表现就是编译全过、一链接满屏
  `undefined reference to mosquitto_xxx`。摆成标准 `libmosquitto.so` 后 3.16 / 3.22 都认；
- ELF 里记录的 `NEEDED` 取库自带的 `SONAME`（`libmosquitto.so.1`），运行时
  `RUNPATH=$ORIGIN` 加载 `deployed/libmosquitto.so.1` 的逻辑不受影响；
- `build-on-box.sh` / `check-box-env.sh` / `deploy-wsl.sh` 用同一套 glob 逻辑（`[ -s ]` 判非空）。

排查命令（盒子上）：

```bash
ls -l third_party/mosquitto/lib/aarch64/     # 应看到 101400 字节的 libmosquitto.so.1.6.9
md5sum third_party/mosquitto/lib/aarch64/libmosquitto.so.1.6.9
# 期望: 609c1ee43b0b526c2b0a731188d7b064
file third_party/mosquitto/lib/aarch64/libmosquitto.so.1.6.9
# 期望: ELF 64-bit LSB shared object, ARM aarch64 ...

# 链接行里到底有没有这个库（编译完看一眼，能一眼看出问题出在 configure 还是链接）
grep -o '[^ ]*mosquitto[^ ]*' build-box/src/CMakeFiles/main.dir/link.txt
# 期望: ../third_party-libs/libmosquitto.so

bash check-box-env.sh                        # 第 3 节「仓库内置依赖」应全 OK
```

如果 `ls` 是空的 → 上传源码时 `third_party/` 没传全，重传一次（**保持目录结构**）：

```bash
# Windows 上（Git Bash / PowerShell 都行）
scp -r third_party ztl@<盒子IP>:~/program/washcar-test/
# 或者整包
rsync -av --exclude build-box --exclude deployed ./ ztl@<盒子IP>:~/program/washcar-test/
```

如果之前用旧版本编过、CMake 缓存里留着 `NOTFOUND`，先清一次：

```bash
bash build-on-box.sh clean && bash build-on-box.sh
```

## 6. 两条路线怎么验证的（本机记录）

| 验证项          | 结果                                                                  |
| ------------ | ------------------------------------------------------------------- |
